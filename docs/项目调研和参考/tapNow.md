### 1、个人体验及技术猜测

![[Pasted image 20260729132717.png]]

上传杯子图 + 说“生成 12s 广告”，没有马上生成，返回一个额度以及要求我补全风格；----断定系统会维护一个逐步补全的规格

- **硬约束**：duration=12s、语言、画幅 (9:16/16:9)、是否配音、是否上字幕
- **业务槽位**（常缺）：品牌名/产品名、核心卖点、价格/优惠、CTA、投放平台 (TikTok/IG/YouTube)、目标人群、合规/禁词
- **视觉槽位**（来自图像理解）：材质、颜色、是否有 logo、杯型、场景适配（办公/咖啡馆/居家）
- 从用户自然语言 + 画布上下文里提取能填的槽位（比如“12s”“轻松风”“适合上班族”等）。
- **确定性 validator**：根据“要做 12s 可投放广告”的最低可交付标准，列出缺失字段（例如没品牌名就无法做口播/字幕落款；没平台就无法选画幅/节奏）

有额度提醒,应该 **Billing/Quota 服务**在旁路工作

- **余额查询**：你当前 credits / Tapies
- **成本预估**：根据 duration、分辨率、模型档位、是否要多版本/多镜头，估一个“最低会扣多少”
- **预占（reserve）**：真正开始跑生成任务前，先预占额度，失败再释放（避免并发跑爆账）

大致流程猜测：

- **System Prompt（隐藏策略）**：产品风格规范、合规规则、不要泄露内部提示、如何提问补槽位、如何估算成本展示方式等
- **Canvas Context**：画布上的图片资产（ID + caption/标签）、已存在节点输出（比如你之前生成的文案/分镜）、用户当前指令
- **Spec Snapshot**：当前已填的结构化 spec（JSON）
- **下游模型 Prompt Template**：把 spec 转换成具体“视频模型/图像模型”的指令（镜头列表、每镜头 prompt、负面词、时长分配等）

### 2 如何落地： (不包括用户管理，提示词管理，API路由)

核心MVP路径： **对话收集参数 → 调度 AI 模型 → 返回视频**

```
用户输入层
├─ 无限画布（Canvas）
├─ 图片上传（多个）
├─ 提示词/脚本（文本）
├─ 模特图片
└─ 场景图片

处理层
├─ 图像预处理
├─ 提示词解析
├─ 模型编排
└─ 生成调度

输出层
└─ 视频生成 & 输出
```

### 3、同类竞品参考

### 4、如果从0到1复刻类似产品，参考的开源项目

#### ✅ComfyUI（调研对比项，未采用为画布前端） **GitHub**: `comfyanonymous/ComfyUI`

> **澄清**：ComfyUI 在本项目里**不是画布前端选型**。本项目的画布前端直接基于 [basketikun/infinite-canvas](https://github.com/basketikun/infinite-canvas) 开发（见 `[02]画布模块/README.md`）。ComfyUI 在 x-media 中仅作为 **AI 网关层的一个可选渠道**（见 `[06]AI网关模块/README.md`）——用于下发并执行自建 SD 工作流，产出图像/视频素材。两者角色不同：infinite-canvas 是画布 UI 上游，ComfyUI 是模型执行渠道。

ComfyUI 是目前最强大的开源 node-based 生成式 AI 应用，用户可以通过在画布上连接节点来可视化构建复杂的 AI
工作流，与传统线性界面不同，它对生成过程的每一步都提供完整控制。 [15](https://www.earngenix.com/blog/why-learn-comfyUI)
 ComfyUI 给你一个空白画布，你通过连接"节点"（小型命名处理块）来组成 pipeline。每个节点做一件特定的事：加载模型、编码
prompt、采样图像、解码结果、保存文件。你把它们串联起来，这个视觉 pipeline 就是你的工作流

#### ✅ Vibe-Workflow（最直接的竞品开源复刻） **GitHub**: `SamurAIGPT/Vibe-Workflow`

Vibe Workflow 提供了一个可与 Krea Nodes 媲美的 node-based 编辑器，完全开源、可自定义，可接入任意 AI 后端。你可以用它构建可与
Freepik Spaces 媲美的 AI 图像生成 Pipeline，也可以像 Krea Workflows
一样排序和自动化视频生成任务。 [1](https://github.com/SamurAIGPT/Vibe-Workflow) 其技术栈为：`client/`（Next.js 前端）、
`packages/workflow-builder/`（核心节点编辑器 UI 库）、`server/`（FastAPI 后端）

#### ✅OpenCanvas **GitHub**: `opencanvasai/OpenCanvas`

一个面向创作者的开源 node-based AI 工作流构建器，通过拖拽和连接画布上的积木块来构建复杂的 AI 工作流。 AI

### 5、核心模块怎么拆

看了 open-ai-canvas 的代码结构和 tapNow 的业务逻辑，产品大致拆成 6 块：

1. **画布**——用户主工作台。拖拽节点、连线、框选、素材库、分镜时间轴。关键点是「上下文捕获」：选中画布上哪些资产（图片、文案、参考帧），序列化后塞进
   Prompt
2. **Agent**——槽位补全 + 校验器。用户说"生成 12s 广告"，LLM 提取已填字段、列出缺失字段，缺品牌名就不往下跑，弹卡片让用户补。视觉槽位用
   VLM 自动解析（材质、颜色、有没有 logo）
3. **后端调度**——异步任务队列、Worker 并发控制、失败重试、状态流转
4. **计费配额**——预占制。生成前先冻额度，失败回滚。前端弹出"预计消耗 XX 额度"
5. **AI 网关**——渠道管理（Kling、Runway、Sora 等），渠道并发控制，ComfyUI 工作流下发
6. **素材存储**——OSS 直传，前端拿临时签名 URL 直接上传，不走后端中转

这几个模块之间通过接口/事件通信，前端不能直接调 AI 渠道，所有生成必须走后端任务。

### 7、可能容易踩的坑

1. **视频角色一致性**
   直接文生视频，人物长相衣服每帧都在变。解法：首尾帧 + 角色参考图 + 运镜提示词三件套。Spec 里强制要一张基准图，后续镜头全走图生视频

2. **LLM 输出长 JSON 幻觉**
   让模型一口气输出 10 个镜头的 JSON，格式必炸。解法：先出大纲，再逐镜头生成，用 Function Calling + Schema 约束

3. **大文件上传**
   视频动辄几百 MB，走后端中转内存必爆。解法：OSS 直传，前端拿临时签名 URL 直接传，后端只记录路径

4. **计费并发**
   多任务同时跑，额度校验和扣减有窗口期。解法：预占（Reserve）—— 入队前先冻额度，失败回滚，不用事后对账
